## 资源解释

cgroup CPU 配额为 1600000/100000，即 16 核；内存配额 128849018880 字节，即 120 GiB。宿主机的 os.cpu_count=128 和约 1 TiB 内存不是容器可用配额。

连续采样 codec 的 CPU 占用约 1.04–1.05 核，GPU 0–2%，进程内存约 1.5 GiB；后续 filter 约 1.06 核，GPU 约 1%，每步约 1.25–1.31 秒。采样区间磁盘读取多次为零；没有证据支持磁盘吞吐是主要瓶颈。小模型 eager 逐算子执行、NumPy/设备同步是优先检查对象，不能仅靠增加 CPU 线程解决。

显存少不代表 GPU 漏用：关闭预分配后，运行时按需申请；同样，瞬时 GPU 百分比不等于吞吐率。对于 CASL，短任务还有约数十秒的模型加载、图编译与保存成本。实验应优化完成时间、帧/秒、更新/秒，同时保留公平的计时口径。

## 本地增加的实现

新增可选 TensorFlow 图执行内核及 `preparation_graph.yaml`，当前远端运行未切换。CPU 测试比较了三个阶段的损失和更新，并检查固定 uniform filter 的安全边界；原始 eager 路径保留。图内核没有增加 batch、改精度、增加训练样本，也不把不同实验并发挤到同一张 GPU 上。

尚未在该 GPU 上测量新训练内核的速度，不能承诺特定倍数或满载。当前批次继续产生原版可追踪结果；后续图执行应作为独立执行配置留档。
