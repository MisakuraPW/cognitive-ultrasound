# 从准备批次转入正式创新实验

本页是工具与记录的交接，不是新增的准备任务列表。closure-v4 执行完并阅读状态后，准备阶段即按固定范围结束；负结果与缺外部资产也作为明确结论保留。

## 已有可复用部件

| 需要的能力 | 入口 | 使用边界 |
|---|---|---|
| 官方冻结重建与状态快照 | `preparation/casl.py: Adapter` | 原版与近似加速分别标记，不能混称原版 |
| 硬件预检与实测图执行 | `belief_filter/preflight.py` | 新卡重新检查，不为了占满 GPU 改变科学设置 |
| 同历史预算反事实 | `preparation/closure_budget.py: collect` | 未来真值只能作标签，不能输入策略 |
| 轻量预算条件预测 | `preparation/budget_protocol.py: fit_models` | 只用训练组拟合；当前模板不等于创新点 |
| 严格相同的总预算 | `budget_protocol.py: feasible / funded_action` | 剩余预算必须可兑现，决定发生在当前新观测之前 |
| 无未来信息的策略接口 | `budget_protocol.py: proposal` | 接收上一帧 observables，不能读取目标图、误差标签或未来预算序列 |
| BF 分阶段与冻结续训 | `belief_filter/runner.py`、`preparation/closure_belief.py` | 新训练目录与明确父 checkpoint，不覆盖既有模型 |
| 有界任务与恢复 | `preparation/suite.py: Coordinator` | 新方法用新配置/输出；累计上限、指纹和失败原因保留 |
| 解释性图片与数值留档 | `preparation/closure.py: render_report` | 定性例子用固定位置，不按最好结果挑图 |

这些部件是可复用代码，不要求下一项创新直接修改收尾批次。冻结这批协议和结果，新想法另建配置和输出目录，保留可回到本批基线的对照。

## 一项正式实验怎样进入记录

先由你在现有 Excel 的核心实验表填写研究问题、假设、预测及理由，并决定何时锁定。具体到某个创新点时，再集中核对最相关方法与技术细节；不用重做一轮全领域想法扩张。

执行配置应引用固定的病例清单、基线版本、父权重、总预算、指标、上限和成功/失败解释规则。实验完成后导入事实，预测和锁定内容不回改；Surprise、Belief Update 和路线决定留给你。准备实验的 CSV 单独留档，不覆盖核心实验行。

你可以先利用已下载结果做零 GPU 的分析，也可以直接在冻结 CASL 上试轻量模块。开始正式创新不以“完整重训 CASL”“把 TBIG 全部接好”或“BF 已经全面胜出”为前提。需要哪种底座由该创新点决定，而不是由准备清单不断增长来决定。

## 仍然未知，但不继续自动准备的事项

- TBIG 在缺少兼容数据/官方资产时没有实测结论。
- 当前 BF 是论文启发实现，不能声称恢复了学长原实现或达到其结果。
- 小规模预算和预测结果不能确立新颖性、泛化性、临床可靠性或跨模态优势。
- GPU 上实际通过的运行配置以该批预检记录为准；本地功能测试不替代实际 GPU 测量。

这些是证据边界，不是要求先全部解决的阻塞清单。后续只有在你选择的具体研究问题需要它们时，才将其纳入正式实验。
