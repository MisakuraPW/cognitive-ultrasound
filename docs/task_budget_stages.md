# 两阶段动态预算：小规模先行与64视频正式批次

日期：2026年10月11日。代码入口 `scripts/run_task_budget_stages.sh`，配置 `configs/task_budget_stages.yaml`。本批是新的学习版本，不续用旧E1/E2控制器，不重训CASL或EF。

## 三项实验

|实验|第一阶段|第二阶段|目标|
|---|---|---|---|
|T1|学习4／7／10／14条|固定7条|相同总预算下改善EF，检验观测前的时间分配|
|Q2|固定7条|学习0／2／4／7／14条|平均MSE增幅≤5%、逐帧MSE p90增幅≤10%的工程目标下减少线数|
|T2|固定7条|学习0／2／4／7／14条|相同总预算下改善EF，检验观测后的时间分配|

每项只训练一个因果GRU预算头：16帧统计历史、32隐藏单元。第一阶段没有当前观测；第二阶段含当前覆盖、中间后验、**采集前预测对实际观测的创新残差**，不是仅检查已拟合观测点的残差。沿用TRAIN-only固定12项标度，新增观测量采用固定log压缩。真值、完整当前帧、未来像素和EF标签不进入控制器。

T1/T2使用可行性掩码：对每个视频的暖帧严格分配7×暖帧数的活动阶段预算，因此视频总线数恰好为14×总帧数，首帧10＋4相同。剩余帧数只作为预先规定采集时长的资源约束，不提供未来图像；这种有限时长实验不等同于未知结束时间的无限流部署。记录配额强制／约束比例，不靠事后修改最后几帧补齐。

Q2使用投影对偶更新学习重建约束，双变量只根据TRAIN反馈更新；约束不保证优化一定成功。开发集没有合格点时保留最小违例检查点，报告未达到质量目标。T1/T2不使用MSE作为通过门槛。

共同底座为FP32、两粒子、25步暖启动、每步DPS、原TBIG式EF选线。零补采确实跳过第二次DPS。主干冻结，但DPS保留输入梯度。两阶段数量变化会改变自己的后验、历史及后续选线，不使用缓存拼图冒充真实闭环。

## 数据和小规模复用

启动前一次锁定64 TRAIN、16开发VAL、32新确认TEST。TRAIN／VAL沿用修复批次原32／8名单，再按原始EF分层补充；确认排除登记过的历史名单。所有病例都满足原EchoNet与CASL划分交集，哈希锁定；不按模型结果挑病例。候选不足会在准备时明确停止，不静默减量或复用已看过的TEST。

小规模使用正式课程的前8个TRAIN与前4个开发病例，各实验先执行2遍小规模TRAIN，即16次真实整视频更新。小规模不使用确认集。

正式第1遍只补剩余56个TRAIN；后续再执行3遍完整64视频。因小规模的8例提前多看了一遍，四遍正式课程对应**264次累计更新**，不是256次，也不是264个epoch。各实验使用相同病例／访问序号与显式噪声流；小规模权重、Adam、奖励EMA、Q2对偶变量全部继承。

检查点：16（小规模）、72（完整第1遍）、136（第2遍）、264（第4遍）。开发选择只在72／136／264中进行：T1/T2选择EF MAE最小点，Q2选满足声明质量容差且最省线的点，否则选最小质量违例点。选择冻结之后才读取32确认病例。训练种子42，确认评价种子42／31415，不把两个评价种子说成两次独立训练。

训练和主评价均执行采样策略，避免训练随机动作与部署argmax的结果混写；本批不计算argmax辅助矩阵。REINFORCE只对活动头求导，使用全视频奖励、过去奖励EMA、固定128的score缩放。固定缩放保留视频等权，不按各视频长度改变训练目标权重。CASL与EF无梯度更新，GRU通过真实动作log概率学习，不使用E1局部投影近似梯度。

旧TRAIN中63帧短视频保留。period2的固定32帧EF输入可能无法直接覆盖其中全部帧，该coverage单独记录，不改原视频索引、不声称每帧均直接进入读出。开发和确认需至少64帧。

## 一次启动

要求新实例已经准备原casl推理环境、Torch任务环境、HDF5数据、冻结权重及 `task_budget_ef_repair_v4` 的config／manifest／identity。没有资产时明确报缺失，不安装CUDA、不下载预训练权重。新批次启动检查32GiB空间；运行和续跑底线2GiB。

```bash
cd /root/autodl-tmp/cognitive-ultrasound
source /etc/network_turbo
git pull --ff-only origin main
bash scripts/run_task_budget_stages.sh start
tail -n 40 -F /root/autodl-tmp/outputs_casl/task_budget_stages_v1.console.log
```

默认自动顺序：真实模型probe → 小规模固定对照 → 三项小规模训练 → 小规模评价及资源匹配周期对照 → PILOT_REPORT与健康门槛 → 正式开发固定对照 → 第1／2／4遍训练及开发评价 → 锁定检查点 → 确认固定对照 → 确认学习策略及匹配周期 → 中文报告及已校验分析包。

健康门槛只检查有限参数、实际参数更新、真实任务学习信号、精确线数与周期组成／调用匹配。**指标不漂亮、CI跨零不阻止正式批次。** 明确实现故障、非有限值、无学习信号、身份或缓存损坏则停止并保留结果，不让有问题的试跑进入长任务。没有自动增加模型、超参数、病例或训练遍数。

```bash
bash scripts/run_task_budget_stages.sh status
bash scripts/run_task_budget_stages.sh stop
bash scripts/run_task_budget_stages.sh resume
```

STOP在帧检查点生效；每16帧原子提交图像、掩膜、DPS历史、GRU特征历史、配额、已采样动作与RNG。优化器在完整更新后提交，未提交更新只重做该更新；已提交病例、固定参照、EF窗口和阶段复用。源代码／硬件／权重／数据变化需要独立输出，不能更改旧identity。

换路径时复制配置并通过 `TASK_STAGES_CONFIG=/path/config.yaml`指定；通过第二个脚本参数设置独立输出目录。不要修改正在运行的源码或配置。

## 对照与输出

固定工作点7＋0／7＋4／7＋7／7＋14用于实际质量—预算参照，兼容的小规模病例和EF窗口复用。学习策略的周期对照严格保持两阶段联合预算组合次数、总线数和感知调用数；同一预算序列直接复用推理，不虚构重复测速。开发检查点不反复计算周期，周期对照在小规模和最终确认计算。

`PILOT_REPORT.md`是小规模结果；`REPORT_中文.md`是累计中文报告；`evaluation_cases.csv`和`summary.json`保留逐病例、病例内种子聚合及描述性配对区间。少采线、少调用与实际墙钟时间分开报告，不把低预算等同于GPU提速。正式训练与评价开销明显大于4小时诊断批次，probe给出实测外推，不保证几小时完成。

完成后自动生成小分析tar.gz并核对每个文件哈希，位置／SHA256见`bundle_receipt.json`。它包含报告、配置、名单、阶段结果与训练记录；**不含原始视频、完整帧、GRU／Adam检查点或冻结权重**。这些证据仍保留服务器，按需单独下载。

本批不实现分割训练、联合任务、第一阶段单帧省预算、planning或WM。它们是已讨论的后续研究分支，不隐藏在本轮一键入口中。
