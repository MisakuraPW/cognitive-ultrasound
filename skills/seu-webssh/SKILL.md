# 东南大学智算平台 WebSSH

## 定位项目与会话

在当前目录或其 `cognitive-ultrasound` 子目录找 `scripts/seu_portal/client.cjs`。从别的工作区管理同一个 CASL 项目时，读取**本技能安装目录**的 `checkout.txt`，其中一行是本机的仓库绝对路径。在找到的仓库中执行 `node scripts/seu_portal/client.cjs 操作`。项目约定见仓库 `AGENTS.md`，详细命令与故障处理见 `docs/seu_webssh_client.md`。查本机历史验收时，仓库上一级的 `reports/东南大学智算平台_CASL作业与队列指南.md` 保存了作业号和实测结果。

服务器端的同步、提交目标固定为 `~/casl/cognitive-ultrasound`。用户指定另一个研究项目时，先确认其远端仓库、提交入口和日志目录，再适配客户端。只切换本地工作目录也会命中原 CASL 仓库。

接手时用 `session` 看专用窗口，用 `probe` 确认学校终端和代码版本。窗口已关闭时用 `login` 打开，学校要求认证时请用户在该窗口完成并进入「智算平台 → 远程终端」。终端失联先用 `reconnect`，保留窗口供后续会话复用。后台客户端要在同一 Windows 用户环境运行，需要本机权限时只申请当前客户端操作。凭据由用户在学校页面填写。

## 按用户请求操作

| 用户意图 | 助手执行 |
| --- | --- |
| 看进度或排查历史失败 | 已知作业号直接用 `status ID` 和 `logs ID 80`。未知作业号先查 `queue` 或 `history 14`。GPU 环境检查已写出时可读 `gpu-report ID`。只查历史时保留原作业。 |
| 部署和提交 | 已部署同一版本时直接使用登记的任务。改代码时只提交任务相关文件，本地验证、推送并核对 `origin/main`，再用 `sync` 和 `probe` 核对学校版本。按本次请求执行 `submit TASK [PARTITION]`，记下 `Submitted batch job` 后的作业号。 |
| 等待完成并验收 | 按同一作业号低频查询。排队时看原因，运行后看日志。结束时核对 Slurm 终态、退出码、任务成功标记和结果位置。查询回显中断时可以重读。提交回显中断时先对照队列、历史及提交回执，确认是否已受理再决定重试。 |
| 配置环境或准备新实验 | 先读 `docs/seu_casl.md` 和现有学校启动脚本。通过用户级环境、学校模块和版本化作业脚本部署，计算走学校调度器。真实环境问题的处理见详细指南的“计算环境”一节。 |
| 传数据、权重或结果文件 | 项目源码走 Git。单独文件可走学校平台「文件管理」手工上传或下载。上传结束后刷新目录并核对最终文件。 |

学校 `sync` 遇到退出码 `124` 时，先用 `probe` 核对远端提交。同一 Git 快进可以在网络恢复后重试。日常操作使用后台客户端，桌面代操作需要用户当次明确要求。
